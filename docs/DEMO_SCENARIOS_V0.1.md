# Demo Scenarios V0.1

| Scenario | Expected risk | Core evidence | Recommendation |
|---|---|---|---|
| Clear phishing signals | Critical | Known fictional phishing match, identity mismatch, lookalike, password request | Leave and block |
| Identity mismatch | Caution | Clean reputation does not verify the claimed bank; domain mismatch | Verify independently |
| Unknown new domain | Caution | Unknown reputation and credential request | Verify independently |
| Verified demo domain | Low evidence | Fictional identity match and no known local threat | Proceed with care |
| Misleading subdomain | High | Actual registrable domain differs; password request | Leave |
| Legitimate HTTPS website | Low evidence | HTTPS and no known local match; no identity claim | Proceed with care |
| Benign unfamiliar domain | Low evidence | No known local match and no sensitive request | Proceed with care |
| Legitimate domain with similar word | Low evidence | Similar wording without a selected identity claim | Proceed with care |
| Verified fictional domain requesting credentials | Caution | Identity matches, but a controlled sensitive request remains | Verify context |

All domains use the reserved `.test` namespace. Outcomes are generated by the same engine as the main check flow and are asserted in automated tests.
